# NuttX 编译教程（sim 模拟器，手动可复现）

> 本文是《NuttX 源码学习文档》的第 11 篇，完整记录如何从零开始编译
> Apache NuttX 的 sim（PC 模拟器）版本。本文所有命令均在本机
> （WSL2 Ubuntu 24.04）真实执行验证过，**无需 AI 辅助**，照着敲即可。

---

## 1. 本文适用范围

- **目标平台**：sim（在 PC 上模拟 NuttX 运行，产物是一个普通的 Linux ELF 可执行文件）
- **目标配置**：`sim:nsh`（带 NSH shell，内含 `hello` 示例程序）
- **本机环境**：WSL2 Ubuntu 24.04，gcc 13.3.0，GNU Make 4.3，28 核 CPU
- **源码版本**：NuttX-13.0.1-RC0

> 编译其他真实开发板（如 stm32、esp32）的流程完全一样，只是
> `configure` 时的板子名和交叉编译器不同，本文第 9 节会说明。

---

## 2. 前置条件

### 2.1 需要的软件包

编译 sim 版本只需要最基本的构建工具（在 Ubuntu/Debian 上）：

```bash
sudo apt update
sudo apt install -y build-essential git
```

`build-essential` 提供 `gcc`、`g++`、`make`、`ld` 等。
验证是否装好：

```bash
gcc --version    # 看到 gcc (Ubuntu 13.3.0...) 即可
make --version   # 看到 GNU Make 4.3 即可
```

> 若编译真实板子，还需要交叉编译器（如 `gcc-arm-none-eabi`），sim 版不需要。

### 2.2 磁盘与内存

- 源码 + 编译产物约 2~3 GB，请留足空间。
- 编译建议至少 4 核 CPU、4 GB 内存（`make -j` 并行度见第 5.2 节）。

---

## 3. 获取源码

NuttX 由**两个仓库**组成，必须放在相邻目录（默认约定为 `nuttx` 和 `apps`）：

```bash
mkdir -p ~/nuttxspace
cd ~/nuttxspace

# 1) 内核源码
git clone https://github.com/apache/nuttx.git

# 2) 应用仓库（NSH shell、hello 示例等都在这里）
git clone https://github.com/apache/nuttx-apps.git apps
```

最终目录结构（以本机为例）：

```
/home/nuttx/nuttxspace/
├── nuttx/     # 内核（本文所在目录）
└── apps/      # 应用库
```

> 两个目录的相对位置不能变，NuttX 的构建系统通过 `CONFIG_APPS_DIR`
> （默认 `../apps`）找到应用仓库。

---

## 4. 配置（configure）

### 4.1 首次配置前的清理（可选但推荐）

如果目录里已有旧构建产物或旧 `.config`，先清理，保证从干净状态开始：

```bash
cd ~/nuttxspace/nuttx
make distclean
```

`distclean` 会删除 `.config`、`staging/`、`.o` 目标文件、生成的
`nuttx` 可执行文件等**所有构建产物，但绝不碰源码**。

### 4.2 执行配置

```bash
./tools/configure.sh sim:nsh
```

- `sim`：板子名（`boards/sim/sim/sim/` 目录）
- `nsh`：配置名（该目录下的 `configs/nsh/defconfig`）
- 格式固定为 `<board>:<config>`，其他板子如 `stm32f4discovery:nsh`

执行时会输出大量 `mkkconfig in ...` 信息（扫描 Kconfig 选项），最后看到：

```
#
# configuration written to .config
#
```

即配置成功。生成的文件是根目录下的 `.config`（约 5 万字节，可 `less .config` 查看）。

> 常用配置查看命令：
> ```bash
> ./tools/configure.sh -L            # 列出所有板子
> ./tools/configure.sh -L sim        # 列出 sim 板子的所有配置
> ```

### 4.3 修改配置（可选）

配置好后可用 NuttX 自带的 menuconfig 图形界面增删功能：

```bash
make menuconfig
```

例如添加一个示例程序：`Application Configuration → Examples → Hello, World!`
（`CONFIG_EXAMPLES_HELLO=y`）。保存退出后直接编译即可。

## 5. 编译（make）

### 5.1 基本命令

```bash
make -j28
```

- `-j28`：28 个编译任务并行（改为你的 CPU 核数）
- 不带 `V=1` 时输出精简（每个文件一行），出错时自动显示详细命令

查看 CPU 核数决定 `-j` 值：`nproc`

### 5.2 推荐的完整编译命令

```bash
make -j$(nproc) V=1 2>&1 | tee /tmp/build.log
```

- `-j$(nproc)`：自动使用全部核数
- `V=1`：显示每条完整编译命令（便于排查、便于生成 compile_commands.json）
- `tee /tmp/build.log`：同时把日志存到文件

### 5.3 编译过程会看到什么

- 先编译内核各子系统：`sched/`、`mm/`、`fs/`、`drivers/`、`arch/`（sim）等
- 再编译应用库：`libapps.a`（NSH、hello 都在其中）
- 最后链接出 `nuttx` 可执行文件并生成符号表
- 成功时末尾类似：

```
LD: nuttx
System.map
...
SIM elf with dynamic libs archive in nuttx.tgz
```

### 5.4 编译耗时参考（本机实测）

| 情况 | 命令 | 耗时 |
|------|------|------|
| 全量（1208 个 C 文件，28 核） | `make -j28 V=1` | 约 6 秒 |
| 增量（只改了几个文件） | `make -j28 V=1` | 1~3 秒 |

> 编译失败时，日志最后几行就是错误位置。常见错误见第 8 节。

## 6. 运行验证

### 6.1 启动

```bash
./nuttx
```

会进入 NSH shell 交互界面：

```
NuttShell (NSH) NuttX-13.0.1-RC0
nsh>
```

### 6.2 运行 hello 示例

在 `nsh>` 提示符后输入：

```
nsh> hello
Hello, World!!
```

### 6.3 非交互方式（脚本/管道）

```bash
printf 'hello\npoweroff\n' | ./nuttx
```

`poweroff` 命令让 NuttX 正常退出（模拟器的关机命令）。

### 6.4 常用 NSH 命令

```
nsh> help        # 列出所有命令
nsh> ls          # 查看伪文件系统
nsh> free        # 查看内存使用
nsh> ps          # 查看任务列表
nsh> poweroff    # 退出模拟器
```

## 7. 编译产物说明

编译成功后根目录下生成：

| 文件 | 说明 |
|------|------|
| `nuttx` | **最终产物**：x86-64 ELF 可执行文件（sim 版），直接运行 |
| `nuttx.map` | 链接映射文件（各符号在内存中的地址） |
| `System.map` | 内核符号表（调试、分析启动流程用） |
| `nuttx.tgz` | 打包的动态库归档（sim 版分发用） |
| `staging/` | 中间静态库（`libsched.a`、`libc.a`、`libapps.a` 等） |
| `.config` | 当前生效的配置（相当于"编译说明书"） |

> 真实板子的产物是 `nuttx.bin`（烧录到板子的二进制），sim 版没有这一步。

## 8. 常见问题排查

| 现象 | 原因与解决 |
|------|-----------|
| `make: gcc: Command not found` | 未装编译工具：`sudo apt install build-essential` |
| `configure.sh: Missing <board/config>` | 漏了参数，格式应为 `./tools/configure.sh sim:nsh` |
| 改了 `.config` 后编译报错/行为不变 | 配置没生效，重新执行 `make olddefconfig` 或 `make distclean` 后重新配置 |
| 编译报缺头文件 `xxx.h: No such file` | 一般是配置里缺了对应功能，`make menuconfig` 检查相关选项 |
| 运行 `./nuttx` 卡住无输出 | 模拟器等 stdin 输入，用 `printf 'hello\npoweroff\n' \| ./nuttx` 或直接输命令 |
| 端口/文件冲突（网络示例） | 先 `poweroff` 退出上一个实例，确认无残留：`pgrep nuttx` |
| 想彻底重来 | `make distclean` 后从第 4 节重新配置编译 |

---

## 9. 编译真实开发板（原理相同）

1. 获取交叉编译器，例如 STM32：
   ```bash
   sudo apt install gcc-arm-none-eabi
   ```
2. 配置改为目标板：
   ```bash
   ./tools/configure.sh stm32f4discovery:nsh
   ```
3. 编译：
   ```bash
   make -j$(nproc)
   ```
4. 烧录（不同板子工具不同，产物为 `nuttx.bin`）。
