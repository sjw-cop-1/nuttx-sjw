# 04 内存管理

NuttX 内存管理在 `mm/` 目录，是一个多层次的分配体系。

## 1. 整体结构

```
mm/
├── mm_heap/      通用堆分配器（核心，所有堆的基础）
├── kmm_heap/     内核堆（kernel heap）—— 封装 mm_heap
├── umm_heap/     用户堆（user heap）—— 封装 mm_heap
├── mm_gran/      粒度分配器（granule allocator，适合显存/物理页等固定粒度）
├── mempool/      内存池（固定大小对象，无碎片）
├── iob/          I/O buffer（网络收发缓冲，链式 buffer 池）
├── bin/          用户态 bin heap（旧式）
├── kbin/         内核态 bin heap（旧式）
├── kasan/        KASAN 内存检查（调试用）
├── shm/          共享内存（多进程）
├── tlsf/         TLSF 分配器（可选，实时性更好的算法）
└── kmap/         内核映射
```

## 2. 堆分配器 mm_heap（核心）

### 2.1 设计思想

`mm/mm_heap/` 实现了一个 **首次适配 (first-fit)** 堆：

- 内存被切成 **chunk**（块），每个块有头部记录大小与使用状态
- 空闲块用双向链表串联，分配时按地址顺序找第一个足够大的块
- 释放时与相邻空闲块**合并**（`mm_free.c` 中的 coalesce）

关键文件：
- `mm_initialize.c` —— 堆初始化（把一段内存建成堆）
- `mm_malloc.c` —— 分配（first-fit 搜索 + `mm_shrinkchunk` 切分）
- `mm_free.c` —— 释放 + 合并相邻空闲块
- `mm_realloc.c` —— 重分配（优先原地扩展）
- `mm_memalign.c` —— 对齐分配
- `mm_lock.c` —— 堆互斥锁（`nxsem_` 实现的递归锁，支持中断安全）
- `mm_mallinfo.c` —— 堆统计信息（mallinfo 接口的数据来源）
- `mm_memdump.c` —— 堆内容 dump（调试用）
- `mm_checkcorruption.c` —— 堆完整性检查（`CONFIG_DEBUG_MM` 时可用）

### 2.2 chunk 结构

```c
struct mm_freenode_s  // 空闲块节点（挂在空闲链表中）
{
  size_t size;                 // 块大小（含头部）
  size_t preceding;            // 前一块大小（用于反向合并）
  FAR struct mm_freenode_s *flink;  // 空闲链表
  FAR struct mm_freenode_s *blink;
};
```

分配块头部（`mm.h`）：
- `size` 的低位用作标志位：`MM_ALLOC_BIT`（已分配）、`MM_PREVFREE_BIT`（前块空闲）
- 所以 NuttX 堆块的分配状态就存在 size 字段的 bit 里，省内存

### 2.3 分配流程（mm_malloc.c）

1. 加堆锁（`mm_lock`）
2. 在空闲链表中搜索第一个 size >= 需求的块
3. 若块足够大（剩余 >= 最小块大小），用 `mm_shrinkchunk` 切出多余部分放回空闲链表
4. 标记已分配，返回块数据区指针（头部之后）
5. 解锁

## 3. 内核堆与用户堆（kmm/umm）

- `CONFIG_MM_KERNEL_HEAP` 使能内核/用户堆分离（配合 MPU 保护）
- `kmm_malloc()` 等（mm/kmm_heap/）→ 内核堆；`kumm_malloc()`（mm/umm_heap/）→ 用户堆
- 未使能分离时，两者指向同一块内存
- 内核代码里大量使用 `kmm_malloc`/`kmm_free`，用户态库使用 `malloc`（底层是 umm）
- `mm_heapmember()` 判断地址属于哪个堆

## 4. 粒度分配器 mm_gran

`mm/mm_gran/`：
- 适合分配**固定粒度**的连续内存：帧缓冲（framebuffer）、DMA 缓冲、MMU 页表
- `gran_initialize()` 建立粒度位图，`gran_alloc()` 分配 N 个连续粒度
- 相关 API：`gran_alloc`、`gran_free`、`gran_reserve`、`gran_enter_critical` 等
- 配置：`CONFIG_GRAN`

## 5. 内存池 mempool

`mm/mempool/`：
- 预分配若干固定大小对象，分配/释放 O(1)，无碎片
- 适合网络缓冲、驱动描述符等高频小对象
- `mempool_initialize()`、`mempool_alloc()`、`mempool_free()`
- 支持多级池（`mempool_multiple`），池满时自动向大池/堆申请

## 6. IOB（网络 IO 缓冲）

`mm/iob/`：
- 网络协议栈的缓冲池，`struct iob_s` 是链表节点
- 头尾指针式 buffer，支持 `iob_alloc`/`iob_free`/`iob_copyin`/`iob_copyout`/`iob_clone`/`iob_concat`
- `iob_initialize()` 在启动早期被调用（见 02_启动流程.md）
- 配置：`CONFIG_IOB_NBUFFERS`、`CONFIG_IOB_BUFSIZE`

## 7. 启动早期的内存初始化

回顾 02_启动流程.md 中的顺序：

```
nx_start()
  ├─ kumm_initialize(heap_start, heap_size)   // 用户堆
  ├─ kmm_initialize(heap_start, heap_size)    // 内核堆
  ├─ iob_initialize()
  └─ ...
```

`heap_start` 来自链接脚本（`g_idle_topstack` 之后的内存），由架构代码传入。

## 8. 用户态内存 API 到内核的路径

```
用户态 malloc()            libs/libc/stdlib/lib_malloc.c
  └─> kumm_malloc()        （或 syscall: mm_malloc，见 08_系统调用.md）
        └─> mm_malloc()    mm/mm_heap/mm_malloc.c
```

## 9. 调试技巧

- `CONFIG_DEBUG_MM` + `mm_memdump()`：打印堆中所有块
- `mm_checkcorruption()`：检查堆完整性，堆损坏定位神器
- `CONFIG_MM_FILL_ALLOC` / `CONFIG_MM_FILL_FREE`：分配/释放时填充特征字节（0xAA/0x55），便于在调试器里识别野指针
- KASAN（mm/kasan/）：检测越界访问与 use-after-free

## 10. 建议阅读顺序

1. `mm/mm_heap/mm.h` —— chunk 与空闲链表结构
2. `mm/mm_heap/mm_initialize.c` —— 堆如何建立
3. `mm/mm_heap/mm_malloc.c` —— 分配算法
4. `mm/mm_heap/mm_free.c` —— 释放与合并
5. `mm/mm_heap/mm_lock.c` —— 堆锁（理解中断安全）
6. `mm/kmm_heap/kmm_malloc.c` 与 `mm/umm_heap/umm_malloc.c` —— 双层堆封装
7. 需要时再看 `mm/mm_gran/`、`mm/mempool/`、`mm/iob/`
