# 05 文件系统与 VFS

NuttX 的文件系统在 `fs/` 目录，核心是 VFS（虚拟文件系统）+ inode 树。

## 1. 总体架构

```
用户态: open/read/write/close/ioctl...
  │  (libc / syscall 层)
  ▼
VFS 层: fs/vfs/fs_open.c, fs_read.c, fs_write.c, fs_ioctl.c ...
  │  通过 inode 查找 + file_operations 回调
  ▼
具体文件系统/驱动:
  ├─ 伪文件系统 (pseudo FS): 直接挂在 inode 上（/dev、/proc 等）
  ├─ 挂载的真实文件系统: fs/fat/、fs/tmpfs/、fs/romfs/、fs/cromfs/、fs/spiffs/...
  └─ 块设备/字符设备驱动: drivers/...
```

关键概念：
- **inode**：路径树上的一个节点，代表一个文件/目录/设备
- **file_operations**：文件操作函数表（open/close/read/write/ioctl...）
- **mount**：把真实文件系统挂到 inode 树的某个目录节点上

## 2. inode 树（fs/inode/）

inode 树是 VFS 的地基，根节点 `/` 在 `fs_initialize()`（fs/vfs/fs_initialize.c）时建立。

```c
struct inode          // include/nuttx/fs/fs.h
{
  FAR struct inode *i_peer;     // 兄弟节点（同目录下一个文件）
  FAR struct inode *i_child;    // 子节点（目录的第一个子项）
  FAR struct inode *i_parent;   // 父节点
  uint16_t i_flags;             // FSNODEFLAG_*（目录/文件/挂载点...）
  FAR struct inode_ops_s *u.i_ops;   // 操作函数表（见下）
  FAR void *i_private;          // 私有数据（驱动实例、文件系统超级块等）
  char i_name[NAME_MAX + 1];    // 节点名
};
```

关键文件（fs/inode/）：
- `fs_inodefind.c` —— 按路径查找 inode（`inode_find()`）
- `fs_inodereserve.c` —— 预留/创建路径节点（`inode_reserve()`）
- `fs_inoderemove.c`、`fs_inodeaddref.c`、`fs_inoderelease.c` —— 引用计数管理
- `fs_inodesearch.c` —— 路径解析核心（`inode_search()`）

## 3. 操作函数表

```c
struct file_operations        // include/nuttx/fs/fs.h
{
  int  (*open)(FAR struct file *filep);
  int  (*close)(FAR struct file *filep);
  ssize_t (*read)(FAR struct file *filep, FAR char *buffer, size_t buflen);
  ssize_t (*write)(FAR struct file *filep, FAR const char *buffer, size_t buflen);
  off_t (*seek)(FAR struct file *filep, off_t offset, int whence);
  int  (*ioctl)(FAR struct file *filep, int cmd, unsigned long arg);
  ...
};
```

- 字符设备驱动注册时填这个表（见 06_设备驱动.md）
- 挂载的文件系统也有对应的 `struct mountpt_operations`

## 4. 打开一个文件的完整流程

以 `open("/dev/ttyS0", O_RDWR)` 为例：

```
fs/vfs/fs_open.c: open() / nx_open()
  ├─ inode_find() 解析 "/dev/ttyS0"，找到 inode（fs/inode/fs_inodefind.c）
  ├─ 若 inode 是挂载点：调用 mountpt_operations->open（真实文件系统）
  ├─ 若 inode 是字符设备：调用 file_operations->open（驱动）
  ├─ 分配 struct file 描述符（fd 表，sched/task/ 里每任务一份）
  │    struct file 含: f_inode（指向 inode）、f_ops（操作表）、f_priv（驱动私有）、f_pos（偏移）
  └─ 返回 fd
```

`struct file` 定义在 `include/nuttx/fs/fs.h`：
- `f_priv`：驱动私有数据（例如串口驱动结构体指针）
- `f_pos`：当前读写位置
- 文件描述符表在 TCB 里（`group->tg_filelist`），fd 是小整数索引

## 5. 伪文件系统（pseudo filesystem）

NuttX 的 /dev、/proc 等是**直接挂在 inode 树上的**，不需要格式化/挂载：

- 设备节点：`register_driver()` 创建 `/dev/xxx` inode（见 06_设备驱动.md）
- procfs：`fs/procfs/` 注册为挂载点，动态生成 /proc 下的文件（线程信息、内存、中断统计）
- 伪文件（fs/vfs/fs_pseudofile.c）：支持在 inode 上直接读写内存缓冲区

## 6. 挂载机制

```
mount("/dev/mmcsd0", "/mnt/sd", "vfat", 0, NULL)
```

- `fs/mount/fs_mount.c`：查找文件系统注册表（`g_fileystems[]`，fs/filesystem/fs_registerfs.c 注册）
- 调用文件系统的 `mount` 回调 → 分配超级块 → 把文件系统 inode 挂到目标目录节点（设置 `FS_FLAG`）
- 卸载 `umount`：fs/fs_umount.c

文件系统目录速览：
- `fs/fat/` —— FAT12/16/32（最常见，配合 mmcsd 驱动）
- `fs/tmpfs/` —— RAM 临时文件系统
- `fs/romfs/`、`fs/cromfs/` —— 只读 ROM 文件系统
- `fs/procfs/` —— 进程/内核信息（类似 Linux /proc）
- `fs/nfs/` —— 网络文件系统
- `fs/unionfs/` —— 联合挂载
- `fs/hostfs/` —— 宿主机文件系统（sim 模拟器用）

## 7. 读写路径示例

```
read(fd, buf, len)
  └─> fs/vfs/fs_read.c: file_read()
        └─> f_ops->read(filep, buf, len)     // 驱动或文件系统实现
```

- 块设备有缓冲层：`fs/driver/fs_blockproxy.c`（块代理，给块设备加 read-modify-write 缓冲）
- 字符设备直通
- `fs/vfs/fs_poll.c`：poll/select 实现，驱动通过 `pollnotify()` 通知

## 8. 建议阅读顺序

1. `include/nuttx/fs/fs.h` —— inode、file、file_operations 三大结构（最核心）
2. `fs/inode/fs_inodereserve.c` + `fs_inodefind.c` —— inode 树操作
3. `fs/vfs/fs_open.c` —— 打开文件全流程
4. `fs/vfs/fs_read.c` / `fs_write.c` —— 读写路径
5. `fs/vfs/fs_initialize.c` —— 根节点建立
6. `fs/mount/fs_mount.c` —— 挂载机制
7. 挑一个真实文件系统读：`fs/tmpfs/`（最简单，纯内存）或 `fs/fat/`（最常用）
8. `fs/procfs/` —— 了解内核信息怎么暴露给用户
