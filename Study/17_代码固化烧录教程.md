# 代码固化（烧录）教程 —— M144Z-M3 / STM32F103ZET6

> 本文是《NuttX 源码学习文档》第 17 篇。把编译好的 NuttX 固件**写进开发板
> 的片内 Flash**，并让它**上电自己就跑**（不依赖 J-Link 调试会话）。
>
> 环境：WSL2 Ubuntu + J-Link + 正点原子 M144Z-M3。所有命令本机验证过。

---

## 0. 「固化」到底是哪两件事

很多人以为 F5 调试和"固化"是两码事，其实：

| 步骤 | 说明 | 现状 |
|---|---|---|
| **① 写进 Flash** | 把 `nuttx.bin` 写到 `0x08000000` 开始的片内 Flash。Flash 是非易失的，掉电不丢 | F5 的 `load`、烧录任务、`JLinkExe` 都在做这件事 |
| **② 上电自启** | 芯片一上电/复位，CPU 从 `0x08000000` 取 SP/PC 开始执行你的代码 | 取决于 **BOOT0 引脚电平**（见第 4 节） |

所以"固化失败"通常不是 ① 没写进去，而是 ② BOOT0 没设对 —— 代码在 Flash 里躺着，但 CPU 复位后跑去了 ST 出厂 bootloader。

**固件三个文件的区别：**

| 文件 | 是什么 | 烧录用途 |
|---|---|---|
| `nuttx` | ELF，带调试符号 | J-Link/gdb 调试用；J-Flash 也能直接烧（自带地址信息） |
| `nuttx.bin` | 纯二进制，无地址信息 | 烧录时**必须指定起始地址** `0x08000000` |
| `nuttx.hex` | Intel HEX，自带地址 | J-Flash / STM32CubeProgrammer 直接烧，不用填地址 |

本教程主要用 `nuttx.bin` + 显式地址。

## 1. 前置检查

```bash
cd /home/nuttx/nuttxspace/nuttx

# 1) 有固件
ls -l nuttx.bin nuttx.hex || make -j$(nproc)

# 2) J-Link 已透传进 WSL
lsusb | grep -i 1366:1020 || bash ~/bin/jlink-attach.sh

# 3) 工具在
which JLinkExe          # 期望 /usr/local/bin/JLinkExe
```

固件大小要 ≤ 512KB（F103ZET6 的 Flash）：

```bash
arm-none-eabi-size nuttx      # text+data 之和就是要烧的字节数，本板约 100KB，够宽
```

## 2. 方式一：VS Code 任务（最省事）

`Ctrl+Shift+P` → `Tasks: Run Task` → **`NuttX: 编译并烧录 (J-Link)`**

它做：`make -j` → `JLinkExe` 把 `nuttx.bin` 写进 Flash → verify → 复位运行。

> 这个任务**不进调试会话**，纯烧录。烧完直接看串口。

---

## 3. 方式二：命令行脚本（推荐，自包含）

已备好 `~/bin/nuttx-flash.sh`：

```bash
bash ~/bin/nuttx-flash.sh              # 编译 + 烧录 + 复位运行
bash ~/bin/nuttx-flash.sh --no-build   # 跳过编译，直接烧现有 nuttx.bin
bash ~/bin/nuttx-flash.sh --verify     # 烧完多做一次全片校验
```

脚本内部就是下面第 4 步那套 JLinkExe 命令，加了 J-Link 自动透传 + 编译 + 大小提示。

预期输出关键行：

```
J-Link: Flash download: Bank 0 @ 0x08000000: N range affected
J-Link: Flash download: Program & Verify speed: ...
Verify successful.
[flash] 完成。板子已复位。
```

> `N range affected` 只写了变化的扇区（J-Link 智能烧录）。第二次烧同一个固件
> 可能显示 "1 range affected (2048 bytes)"，正常。

## 4. 方式三：一条 JLinkExe 命令（理解原理）

```bash
cd /home/nuttx/nuttxspace/nuttx

JLinkExe -device STM32F103ZE -if SWD -speed 4000 -autoconnect 1 \
  -CommanderScript <(cat <<'EOF'
connect
halt
loadbin nuttx.bin 0x08000000
verifybin nuttx.bin 0x08000000
r
g
qc
EOF
)
```

逐行：

| 命令 | 作用 |
|---|---|
| `connect` | SWD 连接 STM32F103ZE |
| `halt` | 停核 |
| `loadbin nuttx.bin 0x08000000` | **擦除相关扇区 + 写入**（loadbin 自带按需擦除） |
| `verifybin nuttx.bin 0x08000000` | 回读比对，确认写对了 |
| `r` | 复位（SYSRESETREQ 软复位） |
| `g` | 运行 |
| `qc` | 退出并断开 |

## 6. 关键：BOOT0 —— 让它"上电自启"

### 6.1 为什么

STM32F103 复位时按 **BOOT0 / BOOT1 引脚电平**决定从哪启动：

| BOOT0 | BOOT1 | 启动区 |
|---|---|---|
| **0 (GND)** | x | **主 Flash `0x08000000`（你的代码）** ← 要的就是这个 |
| 1 | 0 | 系统存储器（ST 出厂 DFU bootloader，`0x1FFFF000`） |
| 1 | 1 | 内置 SRAM |

F103 **没有**"强制从 Flash 启动"的选项字节（不像 F4 的 BFB2）。**BOOT0 引脚电平是唯一开关。**

### 6.2 判断你的板子需不需要改

**最简单：烧完直接实测**（第 7 节）。如果拔掉 J-Link、纯 USB 供电，串口能看到
`nsh>` → BOOT0 已经对了，跳过本节。

**用 J-Link 看**（注意：J-Link 的 `r` 是软复位 SYSRESETREQ，**不重新采样 BOOT0**，
所以这里看到的 PC 在 Flash 不代表上电也在 Flash）：

```bash
JLinkExe -device STM32F103ZE -if SWD -speed 4000 -autoconnect 1 \
  -CommanderScript <(printf 'connect\nhalt\nr\nregs\nqc\n')
```
- `PC = 0x080xxxxx` → 主 Flash 启动
- `PC = 0x1FFFxxxx` → 进了 bootloader，**BOOT0 = 高，必须改**

真正准确的判断还是**断电后再上电**测串口。

### 6.3 怎么改

正点原子 M144Z-M3 上，RESET 键旁边有 `BOOT0` / `BOOT1` 两组排针（丝印 `B0` `B1`）：

- 把 **BOOT0 的跳线帽插到 `GND` 那一侧**（通常是 3 针，中间是 BOOT0，两边分别 3.3V / GND）。
- 或若是 2 针 + 板载上拉：把跳线帽拔掉后短接到 GND。
- BOOT1 保持 0（接 GND / 默认即可）。

### 6.4 改完验证

```bash
JLinkExe -device STM32F103ZE -if SWD -speed 4000 -autoconnect 1 \
  -CommanderScript <(printf 'connect\nRSetType 2\nr\nregs\nqc\n')
```
`RSetType 2` = 用 NRST 硬件复位（会重新采样 BOOT0）。`PC` 应为 `0x080xxxxx`。

## 7. 验证"固化"成功

**这一步必须断开调试器做**，否则测不出 BOOT0 是否正确：

1. 关掉 VS Code 里所有调试会话，退出 JLinkExe。
2. **拔掉 J-Link**（只留 J-Link，不留调试连接也行；最干净是物理拔掉）。
3. 给板子断电，再用 USB（CH340 口）重新上电。
4. 打开串口终端（`/dev/ttyUSB0` 或 Windows COM 口，**115200 8N1**）。
5. 按板上 **RESET** 键。

**期望看到**（`__start` 会先吐几个启动进度字符）：

```
ABⁿDF
NuttShell (NSH) NuttX-13.0.1-RC0
nsh>
```

看到 `nsh>` = 固化成功，代码已经在板子里自主运行。

如果串口**一片空白**：
- 十有八九 BOOT0 = 高 → 回第 6 节改跳线。
- 或串口线/波特率不对（先确认按 RESET 时有没有那几个进度字符）。

## 8. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| `Cannot connect to target` | J-Link 没透传：`bash ~/bin/jlink-attach.sh`；或降速 `-speed 1000` |
| `loadbin` 报 `Failed to erase` | 供电不足 / SWD 干扰；换线、降速、确认板子单独供电 |
| `verifybin` 失败 | Flash 写保护？F103 一般无。或 `nuttx.bin` 损坏，重新 `make` |
| 烧录成功但断电重启没反应 | **BOOT0 = 高**（第 6、7 节）。这是最常见的"固化失败" |
| 串口只有乱码 | 波特率不对，必须 **115200**；或 8 数据位/无校验/1 停止位没设对 |
| 每次 F5 都要重烧 | 正常。`launch.json` 的 `overrideLaunchCommands` 里有 `load`，F5 会自动烧当前构建 |
| 想烧但不想编译 | `bash ~/bin/nuttx-flash.sh --no-build` |
| 换了 `.config` 后忘了重编就烧 | 烧的是旧 `nuttx.bin`。`make -j` 后再烧，或直接用不带 `--no-build` 的脚本 |
