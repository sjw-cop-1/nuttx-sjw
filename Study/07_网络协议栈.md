# 07 网络协议栈

NuttX 网络协议栈在 `net/` 目录，是一个 BSD socket 风格的轻量协议栈。

## 1. 总体分层

```
用户态: socket() / bind() / listen() / accept() / connect() / send() / recv()
  │  (libs/libc/net + syscall 层)
  ▼
socket 层: net/socket/     (net_socket.c, net_bind.c, net_connect.c ...)
  │
  ▼
传输层:
  ├─ TCP:  net/tcp/        (tcp_input.c, tcp_output.c, tcp_send.c ...)
  ├─ UDP:  net/udp/        (udp_input.c, udp_send.c ...)
  ├─ ICMP: net/icmp/, net/icmpv6/
  └─ 其他: net/igmp/ (组播), net/mld/, net/ipfilter/
  │
  ▼
网络层:
  ├─  IPv4: net/ipforward/ (转发), net/ipfrag/ (分片)
  ├─  IPv6: net/sixlowpan/ (6LoWPAN), net/neighbor/ (邻居发现)
  └─  ARP:  net/arp/
  │
  ▼
设备接口层:
  ├─ net/devif/    (devif 框架：设备与协议栈的统一接口)
  ├─ net/netdev/   (网络设备管理: netdev_register, netdev_rx ...)
  ├─ net/route/    (路由表)
  └─ 驱动: drivers/net/  (网卡驱动调用 devif 接口)
```

## 2. 关键数据结构

### 2.1 socket 与连接

- `struct socket`（net/socket/socket.h）：socket 描述符，含 `s_conn`（指向连接结构）
- TCP 连接：`struct tcp_conn_s`（net/tcp/tcp.h）—— 协议控制块 PCB：
  ```c
  struct tcp_conn_s
  {
    /* 链表节点（所有 TCP 连接串起来） */
    FAR struct tcp_conn_s *flink;
    /* 状态: TCP_* 状态机（LISTEN/SYN_SENT/ESTABLISHED/...） */
    uint8_t tcpstateflags;
    /* 序号与窗口 */
    uint32_t sndseq;       // 发送序号
    uint32_t rcvseq;       // 接收序号
    uint32_t snd_wnd;      // 发送窗口
    /* 地址 */
    in_addr_t laddr; uint16_t lport;   // 本地地址/端口
    in_addr_t raddr; uint16_t rport;   // 远端地址/端口
    /* 回调: 数据到达/可写/关闭通知 */
    FAR struct devif_callback_s *conncb;
    ...
  };
  ```
- UDP：`struct udp_conn_s`（net/udp/udp.h），结构类似

### 2.2 devif 设备接口

`net/devif/` 是协议栈与网卡驱动之间的**统一接口层**：

- `struct net_driver_s`（include/nuttx/net/netdev.h）：每个网卡一个实例
  ```c
  struct net_driver_s
  {
    FAR struct net_driver_s *flink;   // 网卡链表
    /* 缓冲区：驱动与协议栈共享 */
    FAR uint8_t *d_buf;     // 收发共用缓冲区（含链路层头）
    uint16_t d_len;         // 当前帧长度
    /* 链路层地址 */
    uint8_t d_mac[6];       // 本机 MAC
    /* 回调链表 */
    FAR struct devif_callback_s *d_devcb;
    ...
  };
  ```
- **单缓冲区设计**：NuttX 用一块共享缓冲，协议栈在中断里处理收包，驱动在轮询时发包
- `devif_poll()`：驱动空闲时询问协议栈"有没有要发的包"
- `devif_reply()` / `devif_forward()`：回应包
- `devif_callback_s`：协议栈在设备上挂的回调（收到包、可以发包、超时等事件）

## 3. 收包流程（以 TCP 为例）

```
网卡中断
  └─> 驱动 ISR: 读 DMA → 数据放入 dev->d_buf, dev->d_len = 长度
        └─> netdev_rx() / devif_input()   (net/netdev/netdev_rx.c 或 devif/devif_input.c)
              ├─ 链路层剥头（eth 帧）: net/ethernet/eth_in.c
              ├─ IP 层处理: ipv4_input() / ipv6_input()
              ├─ 查 TCP 连接表（按 4 元组）找到对应 tcp_conn_s
              ├─ tcp_input(): 状态机处理（SYN/ACK/数据）
              │    ├─ 数据入连接接收队列
              │    └─ 唤醒等待 recv 的任务（sem_post）
              └─ 需要回包时: devif_reply() 构造 ACK 回包
```

## 4. 发包流程（以 TCP 为例）

```
send() → net/socket/net_send.c → psock_send()
  └─> tcp_send() (net/tcp/tcp_send.c)
        └─> tcp_output() (net/tcp/tcp_output.c)
              ├─ 数据拷入 dev->d_buf，构造 TCP/IP/ETH 头
              ├─ 若驱动忙: 挂入发送等待队列，注册"可发"回调
              └─ 驱动轮询: devif_poll() → 回调把包交给驱动 → 驱动写 DMA 发送
```

## 5. socket 层（net/socket/）

- `socket()` → `psock_socket()` → 按 domain/type 创建协议控制块
- `net_socket.c` 是入口，支持 `CONFIG_NET_SOCKOPTS`（socket 选项）
- 文件描述符集成：socket fd 与 VFS 的 fd 表复用（`fs/vfs/fs_socket.c` 或通过 `sockfd`），
  所以 `read()/write()` 也能用于 socket（内部转成 recv/send）
- `net/socket/` 下有 `net_poll.c`：socket 的 poll/select 支持
- 用户态 socket API 在 `libs/libc/net/`，如 `lib_socket.c`，通过 syscall 进内核

## 6. 其他重要模块

| 模块 | 路径 | 说明 |
|------|------|------|
| ARP | net/arp/ | IPv4 地址解析（arp_table 缓存） |
| 邻居发现 | net/neighbor/ | IPv6 ND |
| 路由 | net/route/ | 路由表（net_addroute） |
| 本地 socket | net/local/ | Unix domain socket（进程间通信） |
| 6LoWPAN | net/sixlowpan/ | IPv6 over IEEE 802.15.4 |
| 蓝牙 | net/bluetooth/ | BLE 协议栈接口 |
| 网络过滤 | net/ipfilter/ | IP 过滤（类似 iptables 雏形） |
| NAT | net/nat/ | 网络地址转换 |
| 用户态 socket | net/usrsock/ | 把 socket 操作转发给用户态守护进程（usrsock） |
| netlink | net/netlink/ | 内核与用户态通信 |
| tun/tap | drivers/net/tun.c | 虚拟网卡 |
| 统计 | net/procfs/ | /proc/net 下的网络统计 |

## 7. 网卡驱动如何写（要点）

驱动只需实现（以 drivers/net/ 下的驱动为参考）：
1. `netdev_register()` 注册 `struct net_driver_s`
2. 收包中断 → 数据拷入 `dev->d_buf` → 调 `devif_input()`（或 `netdev_rx()`）
3. 提供 `devif_poll()` 回调（空闲时被调用，取出发送缓冲的包）
4. 完成发送后 `devif_poll` 返回

## 8. 建议阅读顺序

1. `include/nuttx/net/netdev.h` —— `struct net_driver_s`（设备接口）
2. `net/devif/devif_input.c` —— 收包入口
3. `net/tcp/tcp.h` —— `struct tcp_conn_s`（TCP 状态机字段）
4. `net/tcp/tcp_input.c` —— TCP 收包状态机（对照 RFC 状态图看）
5. `net/tcp/tcp_output.c` —— TCP 发包
6. `net/socket/net_socket.c` —— socket 创建
7. `net/arp/arp_in.c` / `arp_out.c` —— ARP 处理（小且完整，适合入门）
8. 挑一个简单网卡驱动：`drivers/net/` 下找（如 enc28j60、sim 的虚拟网卡）

## 9. 动手实验

- 用模拟器（sim）配置 `CONFIG_NET` + `CONFIG_NET_TCP`，跑 NSH 的 `ifconfig`、`ping`
- `grep -rn "devif_input\|devif_poll" drivers/net/ | head` 看驱动怎么接协议栈
- 打开 `CONFIG_NETDEV_STATISTICS`，用 `/proc/net` 看收发包统计
