# 02 系统启动流程

本文跟随代码走一遍 NuttX 从复位到用户应用运行的完整流程。

## 1. 整体链路

```
CPU 复位
  └─> 架构启动代码（汇编，arch/<arch>/src/...）
        └─> nx_start()          [sched/init/nx_start.c]  内核 C 入口
              └─> 初始化各子系统（任务列表、内存、时钟、中断...）
                    └─> nx_bringup()   [sched/init/nx_bringup.c]  启动用户环境
                          └─> nx_start_application()  启动第一个用户应用
                                └─> CONFIG_INIT_ENTRYPOINT 指定的入口
```

## 2. 架构启动代码（汇编阶段）

每种架构各有实现，以 ARM 为例（`arch/arm/src/`）：

- `arm_vector.S` / `arm_head.S`：复位向量、异常向量表
- 关键动作：设置栈指针 → 清零 BSS → 拷贝数据段 → 使能 MMU/缓存（可选）→ 跳转 `nx_start()`
- `arch/arm/src/common/arm_task_start.c`、`arm_pthread_start.c`：新任务的启动桩（汇编跳板），首次调度时跳到任务入口

阅读建议：汇编部分不用逐行读，知道"设置好 C 环境后调用 nx_start()"即可。

## 3. 内核初始化 nx_start()（sched/init/nx_start.c）

`nx_start()` 是内核第一个 C 函数，用一个状态机 `g_nx_initstate` 记录初始化进度：

```
OSINIT_BOOT
  ├─ tasklist_initialize()      // 初始化全局任务链表数组
  ├─ idle_task_initialize()     // 创建 idle 任务（每个 CPU 一个）
  └─ g_nx_initstate = OSINIT_TASKLISTS

drivers_early_initialize()      // 早期驱动（时钟、串口等，见 drivers/early_initialize.c）
nxsem_initialize()              // 信号量模块初始化

内存初始化：
  kumm_initialize(heap_start, heap_size)   // 用户堆 (UMM)
  kmm_initialize(heap_start, heap_size)    // 内核堆 (KMM)，未使能用户/内核分离时与 UMM 共用
  iob_initialize()                         // I/O buffer 池（网络用）
  idle_group_initialize()
  g_nx_initstate = OSINIT_MEMORY

task_initialize()               // 任务模块
fs_initialize()                 // VFS 根 inode
irq_initialize()                // 中断控制器
clock_initialize()              // 系统时钟（节拍）
timer_initialize()              // POSIX 定时器
nxsig_initialize()              // 信号模块
wdog_initialize()               // 看门狗定时器
...
g_nx_initstate = OSINIT_OSREADY

nx_start_application() 或 nx_smp_start()   // 启动第一个应用任务
```

要点：
- **初始化顺序就是依赖顺序**：先任务列表才能建任务，先内存才能分配，先时钟才能延时
- `g_nx_initstate` 贯穿整个启动过程，某些 API 在 OS 未 ready 前调用会走特殊路径（例如启动早期的 `kmalloc` 直接从堆拿内存而不加锁）

## 4. 启动用户环境 nx_bringup()（sched/init/nx_bringup.c）

`nx_bringup()` 干的事：

1. 初始化用户环境（`CONFIG_INIT_ENTRYPOINT` 相关）
2. 启动 `/bin/init` 等价物：`nsh`（NuttShell）或自定义入口
3. 若配置了 `CONFIG_BOARDCTL`，会调用 `board_app_initialize()` 做板级初始化

关键宏：
- `CONFIG_INIT_ENTRYPOINT`：第一个用户任务的入口函数名（默认 `nsh_main`）
- `CONFIG_USER_ENTRYPOINT`：用户程序入口（`main` 的前身）
- `CONFIG_BOARD_LATE_INITIALIZE`：板级后期初始化钩子

## 5. 第一个应用任务怎么创建

在 `nx_start_application()`（sched/init/nx_bringup.c）中：

- 通过 `nxtask_create()` 创建一个用户任务，入口为 `CONFIG_INIT_ENTRYPOINT`
- 该任务继承 `CONFIG_INIT_STACKSIZE` 指定的栈大小（默认 2048 字节左右）
- 从这一刻起，调度器开始运行，系统进入多任务状态

## 6. 常见疑问

Q: 为什么我在 printf 之前没看到任何输出？
A: 串口驱动需要显式初始化，`drivers_early_initialize()` 或 board 初始化里注册 `/dev/console` 之后，`printf` 才有输出目标。可搜索 `CONFIG_DEV_CONSOLE`。

Q: nx_start 里为什么有些函数带 `nx_` 前缀？
A: NuttX 命名约定：`nx_`/`nxsched_`/`nxsem_` 等前缀表示"内核内部实现"，不带 errno 设置或带特殊语义；用户态 API（`sem_wait`、`task_create`）在 libc 或 syscall 层，内部调用这些内核函数。

Q: SMP 多核时呢？
A: `nx_smpstart()`（sched/init/nx_smpstart.c）负责唤醒其他 CPU，每个 CPU 有自己的 idle 任务与就绪队列，见 03_任务调度.md。

## 7. 建议阅读的文件（按顺序）

1. `sched/init/nx_start.c` —— 全文通读，注意初始化顺序
2. `sched/init/nx_bringup.c` —— 看应用是怎么被拉起来的
3. `arch/arm/src/arm/arm_head.S`（或对应架构）—— 只读前 100 行，理解汇编入口
4. `include/nuttx/init.h` —— OSINIT_* 状态定义
