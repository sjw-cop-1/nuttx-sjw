# 01 NuttX 项目概览

## 1. NuttX 是什么

Apache NuttX 是一个实时操作系统 (RTOS)，强调**标准兼容**与**小体积**：

- 主要遵循 POSIX 与 ANSI 标准（与 Linux 用户态 API 高度相似）
- 可扩展支持 8 位 ~ 64 位微控制器
- 为嵌入式环境补充了一些标准之外的 API（如 VxWorks 风格接口）
- 单内核（monolithic kernel），但支持可选的内存保护单元 (MPU) 与用户/内核模式分离

与其他 RTOS 的对比视角：
- FreeRTOS：仅任务+队列，无 POSIX 接口
- RT-Thread：POSIX 兼容层是后加的
- NuttX：**从底层就是 POSIX 设计**，所以它的 API 面非常接近 Linux

## 2. 顶层目录结构

```
nuttx/
├── arch/          架构相关代码（arm/risc-v/x86/... 每种架构一个子目录）
├── audio/         音频框架
├── binfmt/        可执行文件格式加载器（ELF、NXFLAT、内置应用等）
├── boards/        板级支持：每种开发板一个目录，含 defconfig 与 board 初始化
├── crypto/        加密算法（软件实现）
├── drivers/       设备驱动（串口、GPIO、SPI、I2C、USB、显示、音频...）
├── fs/            文件系统（VFS + 具体文件系统：FAT、procfs、tmpfs...）
├── graphics/      图形框架（NxWidgets 等）
├── include/       公共头文件（POSIX 接口头 + nuttx/ 内核内部头）
├── libs/          库：libc、libm、libnx、libxx(C++)、libdsp
├── mm/            内存管理（堆分配器、粒度分配器、mempool、IOB...）
├── net/           网络协议栈（socket、TCP/UDP、ARP、路由...）
├── openamp/       OpenAMP（异构多核远程处理器通信）
├── sched/         内核核心：任务调度、信号、信号量、消息队列、时钟、wdog
├── staging/       编译中间产物（静态库等）
├── syscall/       系统调用层（用户态 <-> 内核态边界）
├── tools/         构建/配置工具（kconfig、mkconfig 等）
├── video/         视频框架
├── wireless/      无线协议（BLE、IEEE802.15.4 等）
├── CMakeLists.txt / Makefile / Kconfig   构建系统入口
└── Documentation/ 官方文档（.rst 格式）
```

## 3. 核心子系统的代码量感知

- `arch/` 最大（每种 CPU 架构都有完整的启动、中断、上下文切换代码）
- `sched/` 是内核核心，约 20 个子模块，全部是 POSIX 语义的实现
- `drivers/`、`fs/`、`net/` 体量相当，各自独立成体系
- `libs/libc` 是用户态 C 库（很多函数直接透传到 syscall）

## 4. 构建与配置机制（了解即可）

NuttX 使用 **Kconfig** 配置（与 Linux 相同的体系）：

```
tools/configure.sh <board>:<config>   # 配置某个开发板
make                                  # 编译
```

- `boards/<arch>/<chip>/<board>/configs/<config>/defconfig` 保存默认配置
- 配置结果生成 `include/nuttx/config.h`，源码里到处是 `#ifdef CONFIG_XXX`
- Kconfig 文件定义了每个 CONFIG 选项的说明与依赖关系
- 当前目录下有 System.map / nuttx.map，说明本仓库已经编译过（还残留 .o/.gcno 等产物）

## 5. 三个"一切皆文件"的层次

理解 NuttX 的钥匙：**所有设备、所有内核对象都挂在一棵 inode 树上，通过路径访问**。

```
用户程序:  open("/dev/ttyS0")  ->  VFS (fs/vfs/fs_open.c)
                ->  inode 查找 (fs/inode/fs_inodefind.c)
                ->  驱动回调 (file_operations)
```

这条链路贯穿驱动、文件系统、字符设备，读代码时反复出现。

## 6. 阅读入口推荐

| 目的 | 路径 |
|------|------|
| 看启动过程 | sched/init/nx_start.c |
| 看任务创建 | sched/task/task_create.c、sched/pthread/pthread_create.c |
| 看调度核心 | sched/sched/sched_addreadytorun.c、sched_removereadytorun.c |
| 看内存分配 | mm/mm_heap/mm_malloc.c、mm_free.c |
| 看文件打开 | fs/vfs/fs_open.c、fs/inode/fs_inodefind.c |
| 看驱动注册 | drivers/ 下各驱动 + include/nuttx/fs/fs.h 的 register_driver() |
| 看系统调用表 | syscall/syscall.csv |
