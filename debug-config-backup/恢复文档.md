# M144Z-M3 VS Code 一键调试环境 —— 恢复文档

> NuttX (STM32F103ZET6) + J-Link + WSL2 下按 F5 一键「编译 → 烧录 → 停在 __start」的
> 完整环境。用于换机 / 系统重装 / 配置被误删后重建。
>
> 备份快照目录：`debug-config-backup/<时间戳>/`
> 最近一次：`debug-config-backup/20260901-1653/`

---

## 0. 这套环境长什么样

```
Windows 11
 ├─ J-Link Plus (USB)  ──usbipd-win──▶  透传进 WSL2
 └─ WSL2 (Ubuntu, networkingMode=mirrored)
      ├─ arm-none-eabi-gcc / binutils      交叉编译
      ├─ gdb-multiarch                     调试器前端(无 arm-none-eabi-gdb)
      ├─ JLinkGDBServerCLI  (/usr/local/bin)  GDB Server 跑在 WSL 内
      ├─ ~/bin/jlink-attach.sh             保证 J-Link 透传(F5 会调用)
      └─ VS Code (Remote-WSL)
           ├─ .vscode/launch.json  tasks.json  ...
           └─ 扩展: marus25.cortex-debug + mcu-debug.*
```

关键点：

- **mirrored 网络**：WSL 的 `localhost` == Windows 主机，不需要 NAT/IP 穿透。
- **J-Link 在 WSL 内**：通过 usbipd-win 把 USB 设备透传进来，GDB Server 本地跑。
- **没有 `arm-none-eabi-gdb`**：全部用 `/usr/bin/gdb-multiarch`。
- **硬件坑**：这块板子 BOOT0=1，复位进 ST bootloader，launch.json 里有软件兜底
  （从 Flash 向量表载入 SP/PC）。**拨好 BOOT0 跳线到 GND 后要删掉那几段 override。**

## 2. 从零重建（没有备份）

### 2.1 系统包（WSL Ubuntu）

```bash
sudo apt update
sudo apt install -y \
  gcc-arm-none-eabi binutils-arm-none-eabi libnewlib-arm-none-eabi \
  gdb-multiarch bear \
  build-essential git kconfig-frontends \
  usbutils linux-tools-generic
```

已验证版本（够用即可，不必完全一致）：

| 工具 | 版本 |
|------|------|
| arm-none-eabi-gcc | 13.2.1 (15:13.2.rel1-2) |
| gdb-multiarch | 15.1 |
| bear | 3.1.3 |
| JLinkGDBServerCLI | V9.72 |

### 2.2 SEGGER J-Link 软件包

从 <https://www.segger.com/downloads/jlink/> 下 “J-Link Software and Documentation pack for Linux, 64-bit DEB installer”，安装后确认：

```bash
which JLinkGDBServerCLI JLinkExe        # 期望 /usr/local/bin/...
```

### 2.3 WSL2 mirrored 网络（Windows 侧）

`C:\Users\<你>\.wslconfig`：

```ini
[wsl2]
networkingMode=mirrored
autoProxy=true
firewall=true
```

改完 `wsl --shutdown` 重启 WSL。

### 2.4 usbipd-win（Windows 侧）

```powershell
winget install usbipd            # 或从 github.com/dorssel/usbipd-win 下 msi
usbipd list                      # 找到 J-Link 的 BUSID，例如 1-12
usbipd bind --busid 1-12         # 管理员，永久共享
```

WSL 侧内核模块（一般自带）：

```bash
lsmod | grep vhci_hcd || sudo modprobe vhci-hcd
```

### 2.5 passwordless sudo（jlink-attach.sh 需要）

```bash
echo "$USER ALL=(ALL) NOPASSWD:ALL" | sudo tee /etc/sudoers.d/$USER
sudo chmod 440 /etc/sudoers.d/$USER
```

### 2.6 开机自动透传（可选，见 wsl.conf）

`/etc/wsl.conf`：

```ini
[boot]
command=/home/nuttx/bin/nuttx-mirror-watch.sh & /home/nuttx/bin/usbip-debug-boot.sh &
```

`usbip-debug-boot.sh` 会挂载 usbipd helper 目录并每 5s 调 `jlink-attach.sh`。

## 3. 配置文件清单与作用

### `.vscode/launch.json`

| 配置名 | 用途 |
|--------|------|
| `Cortex-Debug: m144z-m3 (J-Link)` | **主用**。cortex-debug 自己拉起 JLinkGDBServer(随机端口)，F5 一键 |
| `cppdbg: m144z-m3 (J-Link @ localhost:2331)` | 备用。原生 C/C++ 插件 + 外部 GDB Server |

要点：
- `executable` = `${workspaceFolder}/nuttx`（**双 nuttx 正确**：workspace 根就是 nuttx 仓库，ELF 也叫 nuttx）
- `overrideLaunchCommands`：替换 cortex-debug 默认的 halt/download/reset 序列，
  含 `load`（烧录）+ BOOT0 兜底（`set $sp/$pc` 从 0x08000000 向量表）
- `overrideResetCommands` / `overrideRestartCommands`：复位/重启按钮的 BOOT0 兜底
- `runToEntryPoint` = `__start`（`arch/arm/src/common/stm32/stm32_start_m3m4_v1.c` —— C 启动流程起点）。改成 `nx_start` / `nsh_main` 可停在更晚的地方
- `preLaunchTask` = `Debug: 编译+透传`

### `.vscode/tasks.json`

| 任务 | 作用 |
|------|------|
| `NuttX: 编译` | `make -j$(nproc)`，`$gcc` problemMatcher |
| `NuttX: 生成 compile_commands.json` | `bear -- make`，供 IntelliSense |
| `NuttX: 编译并烧录 (J-Link)` | 编译 + `run_flash.sh` |
| `J-Link: 确保透传` | `bash ~/bin/jlink-attach.sh`（幂等） |
| `J-Link: 启动 / 停止 GDB Server` | cppdbg 方案用的外部 server（端口 2331） |
| `Debug: 编译+透传` | 复合：`NuttX: 编译` → `J-Link: 确保透传`（Cortex-Debug 的 preLaunchTask） |
| `Debug: 构建并启动 GDB Server` | 复合：编译 → 透传 → 启动 server（cppdbg 的 preLaunchTask） |
| `镜像: *` | 与调试无关，原有的 WSL→Windows 单向镜像同步 |

### `.vscode/settings.json`

- `debug.onTaskErrors: abort` —— 编译失败直接不进调试
- `cortex-debug.*` —— 指定 `/usr/bin` 工具链、`gdb-multiarch`、`JLinkGDBServerCLI` 路径

### `.vscode/c_cpp_properties.json`

- `compileCommands` 指向 `${workspaceFolder}/compile_commands.json`
- 兜底 includePath + `forcedInclude` 到 `include/nuttx/config.h`

### `~/bin/jlink-attach.sh`

幂等地把 J-Link 透传进 WSL：`lsusb` 已有 → 秒退；没有 → 挂载 helper、
按 VID:PID `1366:1020` 找 busid、`usbip attach -r 127.0.0.1`、`chmod 666 /dev/bus/usb/*/*`。
失败非零退出 → F5 中止。

### `~/bin/usbip-debug-boot.sh`

`/etc/wsl.conf [boot]` 调用。挂载 usbipd helper 目录 + 后台循环跑 `jlink-attach.sh`
+ 后台循环 `chmod` USB 节点。

## 5. 验证 F5

1. VS Code 打开 `/home/nuttx/nuttxspace/nuttx`（Remote-WSL）
2. F5 → 选 `Cortex-Debug: m144z-m3 (J-Link)`
3. 期望时序（DEBUG CONSOLE / gdb-server 终端）：

```
J-Link: 确保透传        [jlink-attach] J-Link 已透传
NuttX: 编译             成功
Cortex-Debug 起 server   Connected to target
overrideLaunchCommands   load → Programming flash Done → 绕过 bootloader
```

4. 停在 `__start()`，可从头单步整个 C 启动流程（时钟 → .bss/.data → 串口 → 板级 → nx_start）。

## 6. 故障排查（本环境踩过的坑）

| 现象 | 原因 / 处理 |
|------|-------------|
| `GDB Server Quit Unexpectedly` / `Connecting to J-Link failed` | J-Link 没透传进 WSL。`lsusb \| grep segger`；跑 `bash ~/bin/jlink-attach.sh` 看报错。Windows 端 `usbipd list` 确认是 `Shared`，否则 `usbipd bind --busid <x>` |
| `usbip: error: Attach ... failed - Device busy (exported)` | Windows 侧残留 `Attached` 状态但 WSL 已丢。`jlink-attach.sh` 现在会自动 `usbipd detach` 后重试；手动: `usbipd detach --busid <x>` 再跑脚本 |
| `usbipd: error: Mounting '...usbipd-win\WSL' within WSL failed` | usbipd-win 4.x 的已知问题。`jlink-attach.sh` 已绕过（直接用 usbip 客户端连 127.0.0.1:3240） |
| `Unable to find executable file at .../nuttx` | 工程没编译或被 `make distclean`。`./tools/configure.sh m144z-m3:nsh && make -j$(nproc)` |
| `EISDIR: illegal operation on a directory` | launch.json 里 `executable` 被误改成 `${workspaceFolder}`（少了 `/nuttx`）。恢复为 `${workspaceFolder}/nuttx` |
| F5 卡住 / 不停在 __start/nsh_main / PC = `0x1FFFFxxx` | **BOOT0=1，芯片进 ST bootloader**。见第 7 节。launch.json 的 override 是软件兜底 |
| `arm-none-eabi-gdb: not found` | 本环境不装它，用 `gdb-multiarch`。检查 launch.json 的 `gdbPath` / `cortex-debug.gdbPath` |
| 断点空心 / 不命中 | ①ELF 与 Flash 不一致：F5 会 `load`，确认编译成功 ②在 Remote-WSL 里打开工程，不要用 Windows 路径 |
| IntelliSense 一片红 | 跑任务 `NuttX: 生成 compile_commands.json` |
| `make` 报 `Clock skew detected` / `modification time N s in the future` | WSL2 无 systemd/NTP，Windows 睡眠恢复后时钟漂移。`sudo ntpdate -u -b ntp.aliyun.com` 后重编。`usbip-debug-boot.sh` 里已加开机+每 30min 自动同步 |
| `make distclean` 后 F5 报错 | distclean 会删 `.config`/`Make.defs`/`nuttx`。必须重新 `./tools/configure.sh m144z-m3:nsh`。只清编译产物用 `make clean` |

## 7. 硬件：BOOT0 跳线（务必修）

寄存器级确认：擦除+烧录 verify OK，但每次复位 `PC = 0x1FFFFxxx`（ST 出厂 DFU bootloader），
说明 **BOOT0 引脚 = 高**。STM32F103 没有"强制从 Flash 启动"选项字节，BOOT0 电平是唯一开关。

**修法**：开发板 RESET 键旁的 `BOOT0` / `B0` 跳线帽拨到 **GND** 侧（跳线帽缺失就补一个到 GND）。
BOOT1 随意。

**验证**：`monitor reset` 后 PC 应为 `0x080001xx`。

修好后，把 launch.json 里这三段删掉（cortex-debug 默认流程就够用）：
- `overrideLaunchCommands` 里最后 3 行（`set $sp` / `set $pc` / `flushregs`），
  或整个 `overrideLaunchCommands` 换回默认（删掉该字段即可，但要保留 `loadFiles`）
- `overrideResetCommands`、`overrideRestartCommands` 整段删除
